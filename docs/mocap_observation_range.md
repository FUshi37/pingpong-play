# 动捕有效观测范围

启动脚本和网页支持调整原始动捕坐标中的 X/Y/Z 接收范围，单位为米。
输入为 mm/cm 时先换算成米，再筛选全部球散点，之后才进行标定和机器人坐标变换。
上下限包含边界；范围内恰好一个候选点才构成有效观测，散点编号变化不影响选择。
范围内没有球或存在多个候选点时，此帧无效，不更新可信位置、观测时间或速度历史。
此设置用于选择球散点，不改变机器人运动安全边界或刚体姿态解析。

启动示例（数值需按实际动捕坐标调整）：

```bash
ENABLE_MOCAP_BALL=true ./RUN_INTERACTIVE_POLICY_SAFETY_PROBE.sh \
  --mocap-observation-x-limits-m=-0.4,0.4 \
  --mocap-observation-y-limits-m=0.5,1.5 \
  --mocap-observation-z-limits-m=0.2,2.0
```

也可以使用环境变量：

```bash
ENABLE_MOCAP_BALL=true \
MOCAP_OBSERVATION_X_LIMITS_M=-0.4,0.4 \
MOCAP_OBSERVATION_Y_LIMITS_M=0.5,1.5 \
MOCAP_OBSERVATION_Z_LIMITS_M=0.2,2.0 \
./RUN_INTERACTIVE_POLICY_SAFETY_PROBE.sh
```

任意一个新范围选项或环境变量被设置后，新范围就会**替代**旧的
`MOCAP_MARKER_X_LIMITS_M` / `MOCAP_MARKER_Z_LIMITS_M`，不会再与旧边界叠加。
未设置的轴或显式空字符串表示该轴不限。例如只指定新 Y 范围时，旧 X/Z 边界也会移除。
不提供任何新选项时，保持原启动配置；网页会显示其实际生效的边界，便于继续调整。
加上 `PROBE_CONFIG_ONLY=true` 可在启动设备前验证参数；NaN、无穷、缺少端点和颠倒的上下限会被拒绝。

网页位于 **Ball source** 下方的“动捕有效观测范围”：

1. 填写 X/Y/Z 的 min / max；某轴不限时同时清空该轴的两个输入框。
2. 点击“应用动捕范围”，等待状态显示“已应用”。编辑输入框本身不改变当前范围。
3. 取消“启用范围过滤”后点击应用，会移除全部空间过滤，恢复按 marker YY 读取。

应用范围不重启 UDP 接收器、控制线程或动捕子进程。旧位置与录制缓存立即失效，速度历史清空，
下一帧符合新范围的数据重新建立有效观测。保留同一 UDP 源已有的时钟同步结果，
不因范围变化重新等待时钟拟合；重复发送相同设置不会反复清空历史。

频率验证见 [mocap_observation_range_20261110.json](../config/policy_validation_reports/mocap_observation_range_20261110.json)：
修改前后分别通过 localhost 发送 120 Hz 和 240 Hz 合成多散点数据；均全部接收并处理，
同时维持约 200 Hz 缓存读取。真实动捕子进程中也验证了按 Y 范围从散点 1 切到散点 2，
旧缓存立即失效且时钟拟合 epoch 不变。控制调度函数与修改前的 AST 一致；
后台快照、浏览器请求及传感器缓存更新仍沿用原来的周期，没有新增轮询或定时器。
这些验证未连接实际动捕设备或机器人，也没有发送硬件命令。

相关回归 352 项通过。另有 8 项既有动捕时钟/标定用例失败，
用本次修改前保存的接收器与输入适配器复跑时，失败项完全相同；未改动这些既有测试及标定文件。

## 自动动捕标定

`RUN_AUTO_MOCAP_CALIBRATION.sh` 支持同名 XYZ 参数及 `MOCAP_OBSERVATION_X/Y/Z_LIMITS_M`
环境变量；这里筛选的是刚体位置，坐标仍为标定前的原始动捕坐标，单位为米。
例如（上下限需按现场坐标调整，并覆盖整个标定路线中的刚体位置）：

```bash
./RUN_AUTO_MOCAP_CALIBRATION.sh \
  --speed-deg-s 3 \
  --settle-seconds 5 \
  --max-attempts 50 \
  --mocap-observation-x-limits-m=0.3,2.0 \
  --mocap-observation-y-limits-m= \
  --mocap-observation-z-limits-m=
```

添加 `--dry-run` 可只校验参数和 50 个姿态，不初始化 ROS、UDP 或发送运动命令。
范围内恰好一个可跟踪刚体且其姿态有效时，才可进入标定采样。
没有候选、多个候选、越界、失跟踪或缺少有效四元数的数据不会用于标定。

启用任意范围参数后，使用空间范围选择刚体，替代原固定 slot/id 的选择方式；
未指定范围的轴不限，上下限包含边界。不提供任何范围参数时继续使用原固定 slot/id。
当前 UDP 实测中，同一物理刚体的 slot/id 随帧变化，不能将这两个字段视为固定身份。
范围模式逐包按空间范围选择唯一候选，允许编号变化；其他物理刚体应始终保持在该范围外。
`selected_rigid_body` 只记录最近接受的 UDP slot/id，便于诊断，不作为后续采样的身份锁。

采样稳定性、跟踪误差、运动速度、发布频率及重试节奏保持原有配置。
进度文件保存范围和最近接受的 UDP 编号；`--resume` 核对并恢复同一空间范围，不锁定临时编号。
已经采集过样本的会话不能更改范围继续混采；修改范围需开始新的标定会话。

接入验证：193 项相关回归通过，包含四个刚体编号的全部 24 种排列和分包回归；
50 个姿态及默认补充候选准备的 `--dry-run` 通过。
运动控制、发布 tick、采样、停留和重试函数的 AST 与修改前一致；未执行实机标定。
验证记录见 [mocap_calibration_range_20261110.json](../config/policy_validation_reports/mocap_calibration_range_20261110.json)。
