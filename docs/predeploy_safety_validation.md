# simcode9 每次实物部署前的安全验证流程

入口为独立脚本 `RUN_PREDEPLOY_SAFETY_VALIDATION.sh`。
本轮只增加测试工具、故障用例和分析文档；控制代码及原启动脚本保持本轮开始时的版本。
用例清单在 `config/predeploy_safety_cases.json`。每次生成独立证据目录，包含
报告、源码/模型/配置 SHA-256、JUnit、原始 ROS 反馈及实际指令、API 请求和停止事件。
默认只跑离线检查，不连接机器人发令。

**当前方案尚未通过实物部署验收。** 已发现的停止缺陷仍需要解决：此前内置仿真低球 done
及无效球后，最后保持包之后约 0.5 秒继续移动 57 / 85 mm，pitch 最大 5.74°。
见 `analysis_results/simcode9_builtin_gap_20261012_141646/report.md`。
一次实测位置保持、停止发包、服务返回成功，都不能证明实际停止。
流程遇到关键失败会中止后续发令；未执行项保留 BLOCKED / NOT_RUN / NOT_COVERED。

## 1. 固定待部署版本，运行离线检查

```bash
./RUN_PREDEPLOY_SAFETY_VALIDATION.sh --plan
./RUN_PREDEPLOY_SAFETY_VALIDATION.sh --offline --profile fplc_gpu1_v172
```

离线检查包括四模型的训练合约、模型/XML 哈希、actor/critic 维度、5 ms 控制时钟、
90 Hz 球历史采样、训练笛卡尔投影算术、实物边界、原生复位、观测配对和前端配置。
原始 probe 对象接受隔离故障注入：缺失/过期/NaN/Inf/错误长度的 q、dq、反馈年龄，
非法网络输出及推理异常，控制循环意外异常，网页非法球向量，旧 Send 请求与 done 恢复。
这些用例没有真实 ROS 发令连接。
当前原始版本对部分非法 dq/负年龄、控制循环意外异常、网页非法球向量的测试会失败。
这是流程发现的待整改项；本轮不修改对应控制逻辑，也不通过 xfail/跳过把失败掩盖掉。

正常、复位、撤销 Send、硬停止与故障路径都检查不得访问 `safety_limiter`。
网页请求不能关闭 FPLC 工作区、开启补偿/动作 shield、改变观测尺度或球采样时钟。
simcode 目录仍由 COLCON_IGNORE 排除，流程不执行 colcon build，也不更改底层参数。

离线返回 0 只表示离线阶段通过，报告中的 `hardwareReleaseReady` 始终为 false。
测试失败、被跳过、没有收集到对应测试，均不能视为已验证。

## 2. 确认内置仿真及控制器可执行外部指令

操作者先确认控制器当前为内置仿真，使用原启动脚本打开探针，Send 保持关闭。
ROS 的 task/control 状态字段不能可靠证明仿真身份或外部随动已启用。

```bash
# 第一个终端：原探针，默认 Send 关闭
./RUN_INTERACTIVE_POLICY_SAFETY_PROBE.sh

# 第二个终端：明确选择内置仿真动态测试，实际会发送命令
./RUN_PREDEPLOY_SAFETY_VALIDATION.sh --builtin-sim \
  --confirm-built-in-simulation --profile fplc_gpu1_v172
```

动态测试不接管已开启 Send 的会话。只连接本机 HTTP 探针，使用独立会话与 arm token，
使用现有慢复位和策略发布路径；不会启用驱动、自动恢复底层随动、扩大边界或改写 q_ref。
不同模型要分别执行整个内置仿真阶段，不能把 V172 的结果当作其他模型通过。

先通过 Send/Reset 对应的原有受监督慢复位准备，再验证原生复位收敛、真实关节确实运动、
指令数值确实更新。只有目标变化而关节静止时，
标记 BLOCKED，禁止给任何运动停止用例 PASS。
控制器上电姿态可能在策略框外，这一点会原样记录；只允许明确的慢复位准备阶段从该
姿态返回原生点。独立监视器检查关节硬限位、起点到目标的关节走廊和复位速度，检查
驱动心跳与反馈断流。实际复位速度 ≤20°/s、反馈差分加速度 ≤80°/s²，关节走廊余量
1°，末端关节目标误差 ≤0.5°；这些是测量验收门槛，原有轨迹设置仍为 15°/s、40°/s²。
复位结束必须持续停稳并进入原有 XYZ/RP 运行边界，才开启策略运动监视和策略测试。
运行中复位若起点已经在策略框内，整个复位过程也必须保持在框内。
独立 ROS 进程读取实际 q/dq、实际指令并用同一球拍 FK 重建 XYZ 与相对 RP。
它独立监视测试驱动心跳、原始反馈、实测边界及速度；测试驱动退出/卡住时请求 StopAllMU，
保留请求和响应证据并观察停止尾段。此进程属于测试工具，尚不构成部署运行时的独立保护。

## 3. 按依赖顺序运行动态停止用例

脚本自动依次执行：Send/Reset 原生慢复位准备 → 正常拖球基线 → 运动中关闭 Send → valid=false 丢球 → 低球 done →
高球 done → 横向出界 done → 停止 HTTP 心跳触发命令租约失效。
每项必须在独立反馈显示机械臂正在运动时触发，观察完整尾段，再检查恢复有效球或重复
旧 token 是否会自动重启。每次重新开始都经过显式慢复位及新 token。

验收使用实际状态，停止之后仍继续检查实物 XYZ/RP；不得只看最后下发目标或冻结后的
actor 记录。位移从故障触发前最后一帧实际位姿计算，停止延迟从触发时刻计算，包含
租约检测时间；必须持续低速至少 0.3 秒，不能先停后反弹。
关节加速度由同一反馈源的 dq 和 header 间隔计算，故障延迟使用同主机单调时钟。
不会把控制器与主机 header 的固定时基偏移当成反馈延迟。
状态观察使用现有 `/step` 的会话所有权检查：独立观察会话的请求被明确拒绝，并返回
缓存状态。脚本确认 `commandRequestIgnored=true`，因此不会刷新发令会话的租约，
无需给控制服务增加接口。

当前统一验收门槛如下，均在清单中显式记录；它们仅用于判定，不参与限幅或重写策略：

| 检查 | 门槛 |
|---|---|
| 实物 XYZ | X[-0.1,0.1]，Y[-0.6,-0.4]，Z[0.95,1.2] m |
| 实物姿态 | 冻结参考不变，roll/pitch ±4°，yaw 无新增限制 |
| 发布路径反馈年龄 | 原有 ≤10 ms，且有限、非负、完整 q/dq |
| 独立采集反馈/指令值更新 | ≥190 Hz；最长采集/更新间隔 ≤20 ms |
| 运动停止前置条件 | 基线关节跨度 ≥0.5°；触发前实测速度 ≥5°/s |
| 停止距离/时间 | 最大球拍位移 ≤20 mm；实际持续停稳 ≤0.7 s |
| 完整停止观察 | ≥1.5 s；末段持续速度 ≤2°/s 至少 0.3 s |
| 关节速度 | [210,210,240,240,300,300,300] °/s |
| 反馈差分加速度 | [1300,1300,1800,3000,3000,3000,3000] °/s² |

20 mm / 0.7 s 是当前测试验收门槛，仍须结合实物间隙与真实制动能力重新评审，
不能当成制造商认证的制动距离。采集指标也不替代发布路径的严格 10 ms 新鲜度。

任一项失败立即关闭 Send，请求底层停止，保存证据，不自动 reset 或恢复随动。
必须先核对实际停止语义、控制器恢复接口和队列清理；不能用扩大姿态范围消除失败。

## 4. 扩展异常矩阵：关键项未覆盖就不能发布通过

清单还要求如下内置仿真故障，它们需要隔离注入接口/独立运行时停止保护。当前自动
驱动未实现这些注入，报告显式标记未覆盖；不能在正常部署 ROS 域里伪造 JointState：

- 反馈断流、延迟、重复、乱序、时钟回退，速度反馈与位置反馈不一致。
- actor 卡住、CPU 饥饿、单步超时、线程异常、后端 SIGSTOP/SIGTERM/SIGKILL、父进程死亡。
- 独立监视器自身死亡、命令传输丢包/积压/重放、恢复后旧队列继续执行。
- 球样本冻结、时间回退、瞬移、异常速度、球源切换和遮挡后错误重捕获。
- 运动中 Reset、模型切换、双客户端争抢、旧 token 重放、反复故障重入。
- 镜像/录制进程挂起、存储满、网页故障对控制与停止线程的影响。
- 运动中的 StopAllMU 是否实际制动、是否取消已接受目标/轨迹、怎样正确恢复外部随动。

只有前面的实际停止路径修复并通过，才继续这些动态注入。离线故障回归通过不能替代
运动中的故障测试。报告的完整内置仿真门槛要求所有 critical 项 PASS，因此这些缺项
会阻止 `builtinSimulationGatePassed=true`，退出状态为非零。

## 5. 实物专属验收与操作者放行

内置仿真不能验证实体急停/制动、真实断电与驱动故障、负载/标定误差、环境碰撞和
图像质量。清单列出 8 项硬件验收，须由操作者在受监督、低速、有实际停止能力的条件下
逐项留证；先验证实体急停及驱动停止，再验证小幅低速指令、真实时延和停止距离。
复核球拍/负载/机械限位、清空运动区域与人员位置，然后再增加任务幅度。

首次实物运行不能直接沿用内置仿真的 200 Hz 稳定性结论：必须重新检查真实 q/dq
新鲜度、指令跟踪、RP/XYZ、加速度、异常停止及重入。任何缺项或失败都要定位和复测。

## 报告和重算

每次报告绑定本次模型和代码版本，修改代码、模型、配置后重新运行；测试期间发生文件
变化会失败。结果保存在 `analysis_results/predeploy_safety_时间_标识/`，失败也会保存报告。

```bash
# 只读重算历史原始反馈；不会更新原报告或发出新版本通过结论
./RUN_PREDEPLOY_SAFETY_VALIDATION.sh --analyze-run analysis_results/某次证据目录
```

`report.json` 供自动门禁读取，`report.md` 供操作者复核。
PASS 指已完成的具体用例；BLOCKED 指前置条件失败；NOT_COVERED 指没有验证手段；
NOT_RUN 指本阶段尚未执行。只有所有内置仿真关键项实际通过，才允许内置仿真门槛通过；
实物最终放行须单独验收，工具不会自动签发硬件安全保证。
